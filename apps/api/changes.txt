AI Video Preview + Finalize Worklog

What I changed
- I updated the backend video-generation flow to support preview frames first, then final video creation after confirmation.
- I kept the UI unchanged and only touched backend code.

Files changed
- `apps/api/app/schemas/ai_video.py`
- `apps/api/app/routers/ai_video.py`
- `apps/api/app/worker.py`
- `apps/api/app/services/ai_video/google_provider.py`
- `apps/api/app/services/ai_video/replicate_provider.py`
- `apps/api/app/ai/providers/gemini.py`

Why those files changed
- `schemas/ai_video.py` needed to accept all provider values used by the worker, including `luma`.
- `routers/ai_video.py` needed to pass the new `action` flag into the job payload.
- `worker.py` needed the actual preview/finalize logic, FFmpeg handling, retries, logging, and cleanup.
- `google_provider.py`, `replicate_provider.py`, and `gemini.py` needed stronger API-key validation and normalized outputs.

Preview flow
- A `text_to_video` request now enters preview mode by default.
- The worker generates ordered preview frames using existing provider methods.
- Frames are capped to a maximum of 60.
- Each frame stores an ordered identifier and a stable output reference.
- Job status becomes `preview_ready`.

Finalize flow
- The same job can be finalized with `action=finalize`.
- The worker reuses stored preview frames instead of regenerating them.
- The worker validates frame order, checks FFmpeg availability, and converts frames into a final video.
- The final video URL is stored back on the job as `final_video_url`.
- Job status becomes `completed`.

Provider reliability updates
- Replicate now validates allowed model IDs before execution.
- Replicate responses now use a consistent `status / output / error` shape.
- Google provider responses now use the same normalized shape.
- Gemini now fails clearly if the Google API key is missing.
- FFmpeg is checked before final video creation so failures are explicit.

Error handling
- Frame generation retries are limited and logged.
- Missing frame URLs fail clearly.
- Missing FFmpeg fails clearly.
- Temporary frame files are cleaned up automatically after use.

Logging added
- Job start
- Preview frame generation
- Final video generation
- Provider responses and retry failures

How the flow works now
- Request enters `app/routers/ai_video.py`.
- Router stores the job and passes `action` and provider data.
- Worker runs preview mode or finalize mode.
- Preview mode returns frame references.
- Finalize mode builds the video from stored preview frames.
- Job record stores the final output.

How to verify
- Send `POST /api/ai/video/text-to-video` with default preview mode.
- Confirm the job becomes `preview_ready`.
- Send the same flow with `action=finalize`.
- Confirm the job becomes `completed` and `final_video_url` is present.
- Confirm `GOOGLE_AI_API_KEY` and `REPLICATE_API_TOKEN` are set before testing provider paths.

Notes
- No endpoint names changed.
- No UI changed.
- The existing job system is still the source of truth.
