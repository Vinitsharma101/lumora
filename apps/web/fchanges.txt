Frontend Image Flow Notes

What I checked
- I looked at the frontend image generation path.
- The main UI is in `src/components/editor/panels/assets/views/ai-image/`.
- The polling and state live in `src/hooks/use-image-gen-polling.ts` and `src/stores/image-gen-store.ts`.
- The frontend still has mock routes under `src/app/api/ai/`.

Why the random image issue can happen on the frontend
- The old frontend route could fall back to `picsum.photos` when no real backend token was available.
- That means the UI could still show an image even when it was not generated from the prompt.
- So the result looked "random" even though the request path seemed successful.

What the UI currently does
- The controls panel takes the prompt, provider, aspect ratio, and style options.
- It saves the request into local image state.
- The gallery shows generated items and the polling hook updates completed jobs.

What to watch for next
- Make sure the frontend calls the real backend path instead of a mock image route.
- Make sure edit mode sends the source image URL in a real field, not only inside the prompt text.
- Make sure polling reads the same job ID format that the backend returns.

Simple summary
- The frontend can create the illusion of a working image request even when it is only showing a placeholder.
- The next frontend step should be to replace mock behavior with a real backend request flow.

Files to change next

Major change in each file
- `controls-panel.tsx`
  - Make the prompt submit flow send the exact text the user wrote.
  - Make edit mode pass the real source image URL in a clear field.
  - Keep style, seed, aspect ratio, and negative prompt values in the same request.
- `src/app/api/ai/generate-image/route.ts`
  - Remove mock image fallback behavior.
  - Send image requests to the real backend instead of generating placeholder images.
- `src/app/api/ai/video/route.ts`
  - Stop returning fake video/image job data.
  - Forward the request to the actual backend route.
- `src/app/api/ai/jobs/[jobId]/route.ts`
  - Stop reading job status from mock/Replicate-only logic.
  - Pull job progress from the real backend job endpoint.
- `use-image-gen-polling.ts`
  - Keep polling aligned with the real job status shape.
  - Update completed/failed image cards only from real backend output.
- `image-gen-store.ts`
  - Keep the UI state shape stable.
  - Only adjust it if the backend response format needs a small mapping fix.

Why these files matter
- These are the places where the UI can accidentally pretend everything worked.
- If any of them use mock data or outdated job shapes, the screen can show a believable image even when the prompt was not sent correctly.
- Cleaning these files should make the frontend tell the truth about what the backend actually returned.

Best order to work in
- First fix the request sender in `controls-panel.tsx`.
- Then replace mock routes in `src/app/api/ai/`.
- Then make polling/stores match the real backend response.
- Finally test the full prompt → job → poll → display flow.

Final connectivity fix

- The polling hook also reads job status from the real backend directly.
- This removes one more layer that could hide the real error.
- I re-ran the frontend production build after this change, and it completed successfully.

Browser error fix
- The backend returns `job_id`, but the UI was expecting `jobId` in a few places.
- I normalized that shape so the browser can keep polling the right job.
- This matters because a missing job ID can make the UI think the API failed even when it actually returned a queued job.

Why this step matters
- If the frontend makes fake jobs or fake images, it becomes impossible to know whether the random output is from the UI or the model.
- Real forwarding makes debugging honest.
- It also helps the polling and gallery show the same data that the backend actually produced.
